# Сравнение языков Python и C# в контексте разработки фронтенда учебного компилятора

## 1. Структурное программирование

| Аспект | **Python** | **C#** |
|--------|-------------|--------|
| Синтаксис блоков | Блоки кода определяются **отступами** | Блоки кода определяются **фигурными скобками `{}`** |
| Ветвления | `if`, `elif`, `else` | `if`, `else if`, `else`, `switch` |
| Циклы | `for` (итерация по коллекциям), `while` | `for`, `while`, `do...while`, `foreach` |
| Особенности | Нет `switch`; блоки чувствительны к пробелам | Поддерживаются `break`, `continue`, `goto` |

**Пример:**

В Python структура определяется отступами; в C# — скобками, что упрощает формальный парсинг.


```python
# Python
for i in range(3):
    if i % 2 == 0:
        print("Чётное")
    else:
        print("Нечётное")
```
```C#
// C#
for (int i = 0; i < 3; i++) {
    if (i % 2 == 0)
        Console.WriteLine("Чётное");
    else
        Console.WriteLine("Нечётное");
}
```
**Вывод:**  
C# имеет более формализованный синтаксис и подходит для классического синтаксического анализа.  
Python проще визуально, но требует специальной обработки отступов при парсинге.

---

## 2. Набор операторов

| Категория | **Python** | **C#** |
|------------|-------------|--------|
| Арифметические | `+ - * / // % **` | `+ - * / % ++ --` |
| Сравнение | `== != < > <= >=` | `== != < > <= >=` |
| Логика | `and or not` | `&& || !` |
| Присваивание | `= += -= *= /=` | `= += -= *= /= %= &= |= ^= <<= >>=` |
| Тернарный оператор | `x if cond else y` | `cond ? x : y` |

**Пример:**

Python использует ключевые слова, C# — символические операторы; в компиляторе это упрощает токенизацию C#.

```python
# Python
x = 10
y = 20
max_val = x if x > y else y
```
```C#
// C#
int x = 10, y = 20;
int maxVal = (x > y) ? x : y;
```

**Вывод:**  
Python предоставляет компактный и гибкий синтаксис, но в C# больше операторов, включая побитовые и составные, что упрощает генерацию кода и оптимизацию выражений в компиляторе.

---

## 3. Базовые типы данных

| Категория | **Python** | **C#** |
|------------|-------------|--------|
| Числа | `int`, `float`, `complex` | `int`, `float`, `double`, `decimal`, `long`, `short`, `byte` |
| Логический | `bool` | `bool` |
| Строка | `str` | `string` |
| Коллекции | `list`, `tuple`, `set`, `dict` | `array`, `List<T>`, `Dictionary<K,V>`, `HashSet<T>` |
| Особенности | Динамическая типизация | Строгая статическая типизация |

**Пример:**

C# требует указания типа;  Python определяет его динамически — влияет на семантический анализ.

```python
# Python
x = 3.14
name = "Alice"
data = [1, 2, 3]
```
```C#
// C#
double x = 3.14;
string name = "Alice";
List<int> data = new List<int> { 1, 2, 3 };
```

**Вывод:**  
C# предоставляет жёсткую систему типов, что облегчает статический анализ и построение таблиц символов.  
Python гибче, но требует анализа типов во время выполнения.

---

## 4. Пользовательские функции

| Аспект | **Python** | **C#** |
|--------|-------------|--------|
| Определение | `def f(a, b):` | `static void f(int a, int b)` |
| Параметры | Именованные, `*args`, `**kwargs` | Типизированные, `ref`, `out`, `params` |
| Возврат | `return` без указания типа | `return` с явным типом |
| Рекурсия | Поддерживается | Поддерживается |

**Пример:**

C# требует указания типов, что делает сигнатуры функций однозначными при разборе и проверке типов.

```python
# Python
def factorial(n):
    return 1 if n == 0 else n * factorial(n - 1)

```
```C#
// C#
static int Factorial(int n) {
    return (n == 0) ? 1 : n * Factorial(n - 1);
}

```

**Вывод:**  
C# требует строгого указания типов и сигнатур, что облегчает анализ и проверку корректности вызовов.  
Python проще для прототипов, но менее формализован при анализе.

---

## 5. Пользовательские структуры

| **Python** | **C#** |
|-------------|--------|
| Определяются через `class`, динамически расширяемы | Определяются через `class` или `struct`, статически фиксированы |
| Нет модификаторов доступа | Есть (`public`, `private`, `protected`) |
| Всё — объекты | Разделение на ссылочные и значимые типы |

**Пример:**

В C# структура фиксирована и статична; Python позволяет динамически изменять объекты во время исполнения.

```python
# Python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y
```
```C#
// C#
public struct Point {
    public int X;
    public int Y;
    public Point(int x, int y) {
        X = x; Y = y;
    }
}
```

**Вывод:**  
C# ближе к строгой объектной модели, удобной для анализа структуры программы.  
Python предоставляет гибкость, но усложняет статическую проверку.

---

## 6. Работа со строками

| **Python** | **C#** |
|-------------|--------|
| Иммутабельные строки | Иммутабельные строки |
| Интерполяция: `f"{x}"` | Интерполяция: `$"{x}"` |
| Конкатенация через `+` | Конкатенация через `+` или `StringBuilder` |
| Много встроенных методов (`split`, `join`, `replace`) | Методы класса `String` и `Regex` |

**Пример:**

В обоих языках интерполяция встроена, но в C# доступен *StringBuilder* для оптимизации.

```python
# Python
name = "Alice"
print(f"Hello, {name}!")
```
```C#
// C#
string name = "Alice";
Console.WriteLine($"Hello, {name}!");
```

**Вывод:**  
C# обеспечивает более формализованные возможности для работы с текстом, что удобно при генерации кода и анализе исходников.

---

## 7. Работа с массивами

| **Python** | **C#** |
|-------------|--------|
| Основные типы: `list`, `tuple`, `array` | Основные типы: `T[]`, `List<T>`, `ArrayList` |
| Динамическая длина | Фиксированная длина (`T[]`) или динамическая (`List<T>`) |
| Срезы (`a[1:5]`) | Нет встроенных срезов, используется LINQ |
| Итерация | `for x in arr` | `foreach (var x in arr)` |

**Пример:**

Python поддерживает встроенные срезы, C# требует LINQ — влияет на сложность синтаксического анализа выражений.

```python
# Python
arr = [1, 2, 3, 4, 5]
print(arr[1:4])
```
```C#
// C#
int[] arr = { 1, 2, 3, 4, 5 };
int[] slice = arr.Skip(1).Take(3).ToArray();
```


**Вывод:**  
C# предоставляет строгую типизацию массивов, Python — гибкость. Для компилятора важнее первый вариант.

## 8. Управление памятью

| **Python** | **C#** |
|-------------|--------|
| Автоматическое управление (GC + reference counting) | Автоматическое управление (GC .NET) |
| Нет контроля над временем освобождения | Возможен `using`, `IDisposable`, `unsafe` |
| Ссылочная модель | Разделение на ссылочные и значимые типы |

**Пример:**

В C# управление ресурсами встроено в язык, что важно при генерации промежуточного кода.

```python
# Python
file = open("data.txt")
data = file.read()
file.close()
```
```C#
// C#
using (StreamReader file = new StreamReader("data.txt")) {
    string data = file.ReadToEnd();
}
```

**Вывод:**  
Оба языка используют сборку мусора, но C# позволяет контролировать ресурсы при необходимости — важно для низкоуровневой оптимизации.

---

## 9. Обработка ошибок

| **Python** | **C#** |
|-------------|--------|
| `try`, `except`, `finally` | `try`, `catch`, `finally` |
| Исключения — объекты любых классов | Исключения — потомки `Exception` |
| Нет типизации исключений | Типизированная иерархия |

**Пример:**

Типизация исключений в C# позволяет детерминированный семантический анализ потока ошибок.

```python
# Python
try:
    x = 1 / 0
except ZeroDivisionError:
    print("Ошибка деления на ноль")
finally:
    print("Завершено")

```
```C#
// C#
try {
    int x = 1 / 0;
} catch (DivideByZeroException) {
    Console.WriteLine("Ошибка деления на ноль");
} finally {
    Console.WriteLine("Завершено");
}
```

**Вывод:**  
C# обеспечивает строгую, типизированную обработку ошибок; Python проще, но менее предсказуем при анализе потока управления.

## 10. Лексика

| Аспект | **Python** | **C#** |
|--------|-------------|--------|
| Разделители | Пробелы и отступы **значимы** | Пробелы и отступы **игнорируются** |
| Комментарии | `#` | `//`, `/*...*/` |
| Блоки кода | Отступы | Фигурные скобки |
| Литералы | Динамические типы | Строгие типы |
| Особенности | Требует токенов `INDENT/DEDENT` | Классическая лексика DFA-типа |

**Пример:**

Для Python лексер должен отслеживать уровни отступов (INDENT / DEDENT), что делает грамматику контекстно-зависимой.

```python
# Python: отступ — часть синтаксиса
if True:
    print("OK")
```
```C#
// C#: отступы игнорируются
if (true) {
    Console.WriteLine("OK");
}
```

**Вывод:**  
Лексер для Python сложнее, требует контекстного анализа; C# — классическая DFA-грамматика.

---

## 11. Синтаксис

| Аспект | **Python** | **C#** |
|--------|-------------|--------|
| Тип грамматики | Контекстно-зависимая | Контекстно-свободная |
| Объявления | Без типов | Тип обязателен |
| Операторы | Минималистичная грамматика | Расширенная, с перегрузками |
| Особенности | Требует обработки отступов | Можно описать в EBNF |

**Пример:**

Наличие ; и {} в C# делает синтаксис формально описываемым в EBNF; Python требует контекстного анализа строк.

```python
# Python
x = 10
y = x + 5
```
```C#
// C#
int x = 10;
int y = x + 5;
```

**Вывод:**  
Для Python необходим модифицированный LL-анализ; C# можно парсить стандартным LL/LR-анализатором.

---

## 12. Семантика

| Аспект | **Python** | **C#** |
|--------|-------------|--------|
| Типизация | Динамическая | Статическая |
| Связывание имён | Позднее | Раннее |
| Области видимости | LEGB (Local–Enclosing–Global–Builtins) | Определяются по `{}` |
| Проверка типов | Во время выполнения | Во время компиляции |
| Перегрузка функций | Нет | Есть |
| Обработка ошибок | Без статической проверки | С типизированной проверкой |

**Пример:**

Python требует поздней проверки типов (runtime), C# — ранней (compile-time).

```python
# Python
x = 10
x = "строка"  # допустимо
```
```C#
// C#
int x = 10;
x = "строка"; // ошибка компиляции
```

**Вывод:**  
Python требует интерпретационной модели. C# — классический компилируемый язык с возможностью строгого семантического анализа.

---

## 13. Практические последствия для компилятора

| Компонент | **Python** | **C#** |
|------------|-------------|--------|
| Лексер | Контекстно-зависимый, нужны `INDENT/DEDENT` | DFA-анализатор |
| Парсер | Требует адаптации LL-грамматики | Стандартные LL/LR-анализаторы |
| Таблица символов | Формируется динамически | Формируется статически |
| Типовая проверка | В рантайме | В compile-time |
| AST | Узлы без фиксированных типов | Узлы строго типизированы |

---

## 14. Классификация по Хомскому

| Критерий | **Python** | **C#** |
|-----------|-------------|--------|
| Класс грамматики | Контекстно-зависимая | Контекстно-свободная |
| Возможность EBNF | Частичная | Полная |
| Анализ | Смешанный (лексико-синтаксический) | Стандартный синтаксический |

---

## 15. Итоговое сравнение

| Критерий | **Python** | **C#** |
|-----------|-------------|--------|
| Простота прототипирования | +++ | ++ |
| Формальная строгость | + | +++ |
| Типизация и статический анализ | + | +++ |
| Контроль структур данных | ++ | +++ |
| Интеграция с парсером (ANTLR и др.) | ++ | +++ |

**Общий вывод:**  
- **Python** — удобен для разработки **учебных интерпретаторов** и прототипов компиляторов, акцент на гибкости и выразительности.  
- **C#** — подходит для реализации **строгого компилятора**, где важны формальные грамматики, статическая типизация и детерминированный анализ.
